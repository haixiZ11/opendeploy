# Demo 对话脚本

业务背景：某医药分销公司上 K/3 Cloud V9，销售订单标准功能不够用，分三次让顾问"李工"做二开。三段共用同一个销售订单扩展，递进展示产品全部核心能力。

录制前准备：
- dev 账套上 `SAL_SaleOrder` 已无历史扩展（`pnpm tsx --tsconfig tsconfig.node.json scripts/list-extensions.ts` 检查；有就先删）
- 状态栏 K/3 项目绿点
- 每段录完关闭客户端再重登（BOS 缓存梗，否则看不到新字段）

---

## 场景 1：扩展销售订单（字段 + 单据体）

**复制以下内容到对话框**：

> 李工，我们这边做医药分销，最近销售订单要加几个东西。
>
> 订单头上加两个字段：一个是客户的合作等级（分 A、B、C 三档），一个是本单的物流方式（自送、快递、客户自提，三选一）。
>
> 然后单据体下面再加一个子表叫"赠品明细"，里面要能填赠品物料、赠品数量、还有按等级打折后的折扣单价。
>
> 你帮我配一下。

**预期 agent 动作**：
- `kingdee_create_extension`（如还没建）
- 加单据头字段：`F_OD_CustomerLevel`（下拉，A/B/C）+ `F_OD_LogisticsType`（下拉，三选一）
- 创建子单据体 `F_OD_GiftEntry`
- 在子单据体里加 base property 字段（物料）+ decimal（数量）+ decimal（折扣单价）

**录制提示**：~60-90s 一镜到底。录完切到 K/3 客户端，新建销售订单截图给观众看新字段已就位。

---

## 场景 2：业务规则 + 表单插件

**复制以下内容到对话框**：

> 李工，赠品这块业务员老填错——经常忘了按客户等级算折扣，要么折扣价填得比正品还高，发出去亏本。
>
> 能不能让系统自动算？A 等级 9 折、B 8.5 折、C 8 折，业务员选完客户等级后赠品折扣价自动出来。
>
> 另外保存订单之前帮我校验两条：赠品折扣价不能超过对应物料的正品价；赠品总数量不能超过正品总数量的 30%——这是风控要求。

**预期 agent 动作**：
- "等级 → 折扣率"是条件查找（A/B/C 各自映射），Calculate 业务规则做不了 if-else → agent 应选 Python 表单插件 `OnEditEvent` 监听 `F_OD_CustomerLevel` change → 遍历 `F_OD_GiftEntry` 重新计算折扣单价
- 校验类（"折扣价 ≤ 正品价" + "总数 ≤ 30%"）走 Python 表单插件 `BeforeF7Select` 或 `BeforeSave` 抛 KDException

**录制提示**：~90-120s。这一段 agent 内部决策（"为啥不用业务规则用 Python 插件"）是关键卖点，录的时候让 agent 把决策理由说出来。

---

## 场景 3：扩展转换规则 + 转换插件

**复制以下内容到对话框**：

> 李工，业务员从销售订单下推到出库单的时候，能不能把赠品那部分的销售类型自动改成"赠品出库"？财务对账时好区分。
>
> 然后销售订单的物流方式也得带到出库单上，仓管要按这个安排发货。
>
> 最好下推完业务员不用手工改，一键过。

**预期 agent 动作**：
- 扩展销售订单 → 出库单的转换规则（Route A 走 bos-bridge）
- 头表字段映射：`F_OD_LogisticsType` → 出库单对应扩展字段
- 单据体子表（`F_OD_GiftEntry`）转换映射
- 转换插件 Python `AfterConvert`：识别赠品行 → 设销售类型为"赠品出库"

**录制提示**：~90-120s。这是产品能力栈最深的一段（写入路径 Route A + 多张表协调），失败一次重试很正常，录的时候不要剪，让观众看到"agent 自己 debug"的真实质感。

## 业务故事真实度依据

- **医药分销 + 赠品打折** = 行业真实痛点（参考真实客户项目 sarcah）
- **客户等级 → 折扣率（A/B/C → 9/8.5/8 折）** = 行业惯例分级定价
- **赠品占比 30% 上限** = 内控合规防避税常见红线
- **赠品出库销售类型区分** = 财务结转和销售报表常见诉求
- 整段对话用顾问惯听口吻（"李工，能不能…"），无技术词污染
